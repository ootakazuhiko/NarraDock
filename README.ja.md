# NarraDock

原稿から音声・動画の制作、レビュー、公開までを扱う汎用制作基盤です。公開の個人プロダクトとして開発します。音声のみの公開を正式な経路とし、映像生成や立ち絵を必須にしません。

## 実装状況

初期実装は、入力JSONの構造検証、処理計画の生成、中立サンプル、テスト、公開ファイル検査です。計画に表示された処理は実行しません。

[プロジェクト別素材台帳と実バイト検証](docs/asset-registry.md)も実装済みです。`narradock_assets.py`の`validate`は台帳の構造を検証し、`verify`は明示した信頼するプロジェクトルート配下の素材を読み取り専用で解決し、実バイトのSHA-256とサイズを照合します。バイト検証の成功は権利確認、媒体QA、公開承認を意味しません。

`narradock_transcript.py`には、[時刻付き文字起こしの契約](docs/synchronized-playback.md)を実装しています。構造検証、呼び出し側が提供する参照情報との照合、文字起こし全体の版を識別するハッシュ、プレーンテキストをエスケープしたWebVTT出力に対応します。実メディアのバイト検証や素材台帳との接続は行わず、ブラウザーでの同期再生は未実装です。`examples/timed-transcript.json`のハッシュと時刻は架空値です。

音声合成、動画生成、実メディアQA、レビュー画面、アップロード、RSS生成、外部公開は未実装です。

`examples/audio-only.json`と`examples/video-enabled.json`のハッシュは引き続き架空値です。`examples/asset-registry.json`には、[素材台帳の再現用サンプル](docs/asset-registry.md#cli-and-a-reproducible-synthetic-example)で説明する合成バイト列のハッシュとサイズを記載しています。実バイトの検証には、そのバイト列の作成と検証処理の実行が必要で、構造検証だけでは一致を確認しません。

## 管理境界

共通コードと中立的な説明だけを公開リポジトリへ保存します。各利用者の原稿、素材、認証情報、実行履歴、レビュー、公開記録は独立した作業領域に置きます。生成成功、技術QA、人間承認、外部転送、公開を同一視しません。

[開発前提と検証](docs/development.md)、[音声公開設計](docs/audio-publication.md)、[開発計画](docs/roadmap.md)を参照してください。音声公開はIssue #2で管理します。公開先と認証方式は未選定です。

製品版はpre-alphaの`0.1.0a1`です。配布パッケージは未公開です。[Codexへの開発引継ぎ](docs/codex-handoff.md)とIssue #7に次の本体開発単位を記録しています。実行・統合の最新状態は、対応するIssueとPRで確認してください。

[音声候補レコード](docs/candidate-records.md)も実装しています。素材1件と配布用情報を候補版の識別値に結び付け、選択した版と実ファイルのバイトが一致するか照合します。候補CLIは標準入力からJSONを読み取ります。パッケージ生成、権利確認、媒体QA、人間の承認、転送・公開許可は含みません。

[ローカル音声パッケージ](docs/local-packages.md)は、別の`narradock_packages.py`のPython APIで作成できます。候補版に紐づく呼び出し側の確認・承認記録を必須とし、コピーしたバイトを検証して、既存出力を上書きせず固定構成のZIPを作ります。候補形式0.2では時刻付き文字起こし1件と申告した音声長を候補版に結び付け、字幕JSONとエスケープ済みWebVTTを同梱します。従来の音声のみ形式0.1の出力は維持します。このAPIは記録の本人確認や権利審査、媒体QA、音声長・発話との同期の実測、転送・公開を行いません。

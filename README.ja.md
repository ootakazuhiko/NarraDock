# NarraDock

原稿から音声・動画の制作、レビュー、公開までを扱う汎用制作基盤です。公開の個人プロダクトとして開発します。音声のみの公開を正式な経路とし、映像生成や立ち絵を必須にしません。

## 実装状況

初期実装は、入力JSONの構造検証、処理計画の生成、中立サンプル、テスト、公開ファイル検査です。計画に表示された処理は実行しません。

[プロジェクト別素材台帳と実バイト検証](docs/asset-registry.md)も実装済みです。`narradock_assets.py`の`validate`は台帳の構造を検証し、`verify`は明示した信頼するプロジェクトルート配下の素材を読み取り専用で解決し、実バイトのSHA-256とサイズを照合します。バイト検証の成功は権利確認、媒体QA、公開承認を意味しません。

[原稿ブロックのAPI](docs/script-contract.md)では、明示された種類に従って本文と制作指示を分離し、文字・改行・順序を保持します。原稿全体と本文だけの識別値、各本文ブロックのUTF-8ハッシュを返します。読み上げ範囲の推測、制作指示の実行、音声生成、既存の処理計画との接続は行いません。

`narradock_transcript.py`には、[時刻付き文字起こしの契約](docs/synchronized-playback.md)を実装しています。構造検証、呼び出し側が提供する参照情報との照合、文字起こし全体の版を識別するハッシュ、プレーンテキストをエスケープしたWebVTT出力に対応します。実メディアのバイト検証や素材台帳との接続は行わず、[合成データによる同期再生デモ](docs/standalone-player.md)を別に実装しています。`examples/timed-transcript.json`のハッシュと時刻は架空値です。

[PCM WAV測定API](docs/audio-measurements.md)では、候補の実バイトを検証しながらフレーム数・音声長・サンプルピーク・端点値のサンプル数・全チャンネルがゼロのフレーム数を測定します。候補形式0.2では申告した音声長とも比較します。対応WAV形式は限定され、測定成功を媒体QAの合格とは扱いません。

[章タイムラインAPI](docs/media-timeline.md)では、PCMフレーム単位の章区間を選択した候補・字幕に結び付け、WAVを再検証して実測した時計と照合します。元のフレーム位置を保持し、絶対位置からミリ秒へ変換して丸め誤差の累積を防ぎます。章の再生UI、音声編集、章の内容と音声の意味的な対応検査は今後の実装です。

音声合成、動画生成、総合的な媒体QA、実際の候補を承認するレビュー画面、アップロード、RSS生成、外部公開は未実装です。

[候補音声のプレビューAPI](docs/candidate-preview.md)では、選択した形式0.2の候補、対応する字幕、検証済みPCM WAVから非公開の視聴用HTMLを生成できます。音声長を実測して照合し、検証時に読み取った同じバイト列を埋め込みます。再生と字幕同期を確認できますが、レビュー完了や承認は記録しません。生成物には音声の付随メタデータも含まれるため、各プロジェクトの非公開領域で扱います。

プレビューには[時刻付き視聴メモ](docs/review-notes.md)を追加できます。位置を固定してメモを入力・編集し、その位置へ移動したり、明示操作でJSONを保存したりできます。保存済みJSONをPythonのプレビューAPIへ渡すと、候補・字幕の版と時刻の参照を照合し、WAVを再検証したうえでメモを復元します。画面での変更を残すにはJSONを保存し、そのJSONからプレビューを再生成します。メモは非公開領域で扱い、レビュー完了や本人確認済みの承認記録とは区別します。

`examples/audio-only.json`と`examples/video-enabled.json`のハッシュは引き続き架空値です。`examples/asset-registry.json`には、[素材台帳の再現用サンプル](docs/asset-registry.md#cli-and-a-reproducible-synthetic-example)で説明する合成バイト列のハッシュとサイズを記載しています。実バイトの検証には、そのバイト列の作成と検証処理の実行が必要で、構造検証だけでは一致を確認しません。

[単体プレーヤーデモ](docs/standalone-player.md)は、テスト音と字幕を含む自己完結したHTMLを生成します。再生・シーク・速度変更・字幕の強調表示・自動追従の切替を試せます。実音声の入力や承認の保存は扱いません。Pythonで生成した後は、ブラウザーだけで操作できます。

デモと候補プレビューで[字幕検索](docs/standalone-player.md#search-the-current-transcript)を利用できます。現在の字幕を部分一致で探し、結果を選ぶと再生・停止の状態を保ったまま該当時刻へ移動します。検索語は画面内だけに保持し、保存済みメモや候補の版は変更しません。

## 管理境界

共通コードと中立的な説明だけを公開リポジトリへ保存します。各利用者の原稿、素材、認証情報、実行履歴、レビュー、公開記録は独立した作業領域に置きます。生成成功、技術QA、人間承認、外部転送、公開を同一視しません。

[開発前提と検証](docs/development.md)、[音声公開設計](docs/audio-publication.md)、[開発計画](docs/roadmap.md)を参照してください。音声公開はIssue #2で管理します。公開先と認証方式は未選定です。

製品版はpre-alphaの`0.1.0a1`です。配布パッケージは未公開です。[Codexへの開発引継ぎ](docs/codex-handoff.md)とIssue #7に次の本体開発単位を記録しています。実行・統合の最新状態は、対応するIssueとPRで確認してください。

[音声候補レコード](docs/candidate-records.md)も実装しています。素材1件と配布用情報を候補版の識別値に結び付け、選択した版と実ファイルのバイトが一致するか照合します。候補CLIは標準入力からJSONを読み取ります。パッケージ生成、権利確認、媒体QA、人間の承認、転送・公開許可は含みません。

[ローカル音声パッケージ](docs/local-packages.md)は、別の`narradock_packages.py`のPython APIで作成できます。候補版に紐づく呼び出し側の確認・承認記録を必須とし、コピーしたバイトを検証して、既存出力を上書きせず固定構成のZIPを作ります。候補形式0.2では時刻付き文字起こし1件と申告した音声長を候補版に結び付け、字幕JSONとエスケープ済みWebVTTを同梱します。従来の音声のみ形式0.1の出力は維持します。このAPIは記録の本人確認や権利審査、媒体QA、音声長・発話との同期の実測、転送・公開を行いません。

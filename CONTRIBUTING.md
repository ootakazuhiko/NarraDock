# Contributing

NarraDock is pre-alpha. License selection and external contribution terms are still open; discuss substantial contributions before submitting code that requires a licensing commitment.

Assign one worktree and one focused branch to a change. Record the actual base/head and concurrent work, then submit a Draft PR. Keep main unchanged until maintainer review and explicit merge authorization. Check remote changes again before publishing updates.

Use only neutral examples and synthetic fixtures. Do not attach real project manifests, media, credentials, private links, customer details, or raw environment dumps to issues or PRs. A public issue is not a private support channel.

Run the validation sequence in docs/development.md. Update public-files.json together with file changes. A successful scanner or CI run does not establish content approval, runtime safety, legal clearance, or publication permission. Keep implemented, proposed, tested, and not-tested claims distinct.

On failure, stop the affected work, preserve evidence privately, and report only sanitized diagnostics. Do not remove tests, broaden permissions, or relax validation. Before reverting local edits, save the assigned diff outside the repository and restore only explicitly assigned files. After merge, use a reviewed corrective/revert PR; do not reset shared branches. Never roll back unrelated work.
